# 客户操作手册

本手册对应 `/delivery/` 的五个步骤按钮。客户数据默认写入 `%LOCALAPPDATA%\CAM Automation Studio\app-data\customer`；应用数据根目录是 `%LOCALAPPDATA%\CAM Automation Studio\app-data`。启动入口会先检查 Python 版本和包内资产。

## 0. 启动与来源确认

1. 双击 `delivery\start_customer.bat`。前置条件是 Python 3.10 或更高版本，不能把 ZIP 当作免 Python 安装包。
2. 启动器会打印提示地址 `http://127.0.0.1:8765/delivery/`；端口占用时重新运行 `delivery\start_customer.bat --port 8766`。
3. 页面顶部应显示“离线审阅”。这表示本机审阅工作台，不表示已连接 NX、PowerMill 或 Cimatron。
4. 没有真实宿主导出时，可用 `delivery\examples\snapshot-fixture.json` 和 `case-fixture.json` 走通流程。这两个文件的 `source`/`provenance.source` 是 `fixture`，只用于演示，不得当作客户数据或加工证明。

宿主只读导出工具的接口和限制见 [host_bridges/README.md](../../host_bridges/README.md)。当前包不自动安装宿主插件；PowerMill/NX 的真实只读导出和版本对应性仍需现场验证。Cimatron 仅提供静态实验解析，不等同于制造快照支持。

## 1. 制造上下文

1. 点击步骤“制造上下文”。
2. 有真实宿主导出的 JSON 时，点击“导入 JSON”，选择文件；没有时点击“载入示例”。
3. 在“已导入快照”列表点击目标快照，检查产品、实例、项目、目标版本、单位、材料、机床轴数。
4. 查看对象绑定状态。对象选择器必须唯一解析；出现“歧义”或“未找到”时，回到宿主导出修正 `object_id`、名称、类型或属性，不要凭经验选第一个。
5. 只有来源、哈希和对象都正确时才进入步骤“案例复用”。导入文件只解析 JSON 数据，不执行其中的代码。

快照模板至少编辑：`product`、`instance_id`、`project_id`、`target_version`、`units`、`material`、`machine.axes` 和 `objects`。真实来源应使用 `source: "imported"`；`source: "fixture"` 只保留给演示数据。

## 2. 案例复用

1. 点击“案例复用”，确认页面提示已选择快照。
2. 在搜索框输入名称、标签或步骤关键字，点击“检索”。
3. 逐张查看案例的产品、材料、单位、机床能力、步骤和来源。匹配说明是筛选/排序依据，不是成功率。
4. 点击“导入案例”可导入客户历史案例；也可点击“载入示例”导入 `delivery/examples/case-fixture.json`。
5. 仅选择产品和制造条件兼容、来源可追溯且已由人员审阅的案例。

案例模板中应编辑 `name`、`product`、`material`、`units`、`machine`、`tags`、`parameters`、`steps` 和 `provenance`。生产案例的 `provenance.source` 应写真实来源和版本；`fixture` 只表示演示来源。

## 3. 建立建议

1. 在案例卡片中选择“建立建议”，进入步骤“建立建议”。
2. 检查建议 ID、案例哈希、快照哈希、对象绑定和缺失条件；确认页面标识为 `dry-run / 待审阅`。
3. 在“建议参数”编辑 JSON 参数（例如 `stepover`）。点击“重新生成”后才会建立新建议；点击“检查门禁”只重新评估当前建议。
4. 任意快照、案例、对象绑定或参数变化都必须建立新建议，不能沿用旧建议或旧证据。新建议不会继承旧建议的证据。

建议是可追溯的参数化审阅对象，不是执行命令；本交付包不输出机床 NC。

## 4. 证据闭环

1. 点击“证据闭环”，依次处理四张卡片：“人工审阅”“CAM 仿真”“碰撞检查”“现场批准”。
2. 每张卡选择“已通过”或“未通过”，填写“操作者”（姓名或工号）和“备注”（范围、软件版本、检查结论）。
3. 点击每张卡的“登记证据”，确认摘要从 `0 / 4` 增加。
4. 证据会绑定当前建议哈希和快照哈希。参数或上下文变化后必须回到步骤 3 重新建立建议。

本地登记仅表示记录已写入本机，**不等于独立认证**。仿真、碰撞检查和现场批准必须由客户按质量流程完成并保存原始记录。

## 5. 导出交付包

1. 点击“导出交付包”。
2. 点击“下载 JSON”，保存可追溯审阅包。
3. 检查导出中的来源、快照/案例/建议哈希、证据和门禁状态。即使仍有阻塞原因也允许下载，但不得把 `blocked` 当作可生产结果。
4. 把导出包和独立仿真、碰撞、现场批准记录一起归档。

## 6. 停服务后备份与恢复

先关闭工作台窗口，确认 `start_customer.bat` 启动的 Python 进程已停止，再备份整个应用数据根目录（不是只备份 `customer` 子目录）：

```powershell
python scripts\customer_self_check.py --json
python scripts\customer_backup.py `
  "$env:LOCALAPPDATA\CAM Automation Studio\app-data" `
  .\customer-backup.zip
```

恢复到新目录进行验收：

```powershell
python scripts\customer_restore.py `
  .\customer-backup.zip `
  "$env:LOCALAPPDATA\CAM Automation Studio\app-data-restore"
```

备份中的 SQLite 数据库使用 SQLite backup API 生成一致快照；停服务仍是推荐流程。恢复默认拒绝覆盖已有文件，只有确认目标后才显式使用 `--overwrite`。恢复会拒绝绝对路径、`..` 越界、Windows 保留设备名、ADS 冒号、末尾点/空格、大小写碰撞、重复成员和符号链接。
